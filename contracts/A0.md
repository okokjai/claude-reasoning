# Contract A0: Mode Routing

**Inputs**
- `data_type` — Data type from A1 contract output
- `primary_domain` — Primary domain from A1 contract output
- `sub_question_types` — (Optional) Sub-question types from A1 contract output
- `specified_mode` — (Optional) Mode explicitly specified by the user; if present, skip routing

**Outputs (Mandatory)**
- `primary_mode` — Routed mode (`diagnostic` / `design` / `decision` / `optimization` / `innovation`)
- `route_rule` — Specific rule name that triggered this route
- `route_confidence` — Routing confidence (`high` / `medium` / `low`)

---

## Routing Rules (Descending Priority)

| Priority | Condition | Routed Mode | Confidence |
|----------|-----------|-------------|------------|
| 1 | `specified_mode` exists | Use specified mode directly | high |
| 2 | `data_type` = external-data + sub_question_types includes price comparison / option comparison | `decision` | high |
| 3 | `data_type` = external-data + `primary_domain` = daily and includes price/timeliness | `decision` | high |
| 4 | `data_type` in (`pure-computation`, `theoretical-derivation`, `personal-context`) + question description includes failure/error/crash/anomaly  *(legacy alias: `internal-logic`)* | `diagnostic` | high |
| 5 | `data_type` in (`pure-computation`, `theoretical-derivation`, `personal-context`) + question description includes design/architecture/solution/refactor  *(legacy alias: `internal-logic`)* | `design` | high |
| 6 | `data_type` in (`pure-computation`, `theoretical-derivation`, `personal-context`) + question description includes bottleneck/performance/optimization/efficiency  *(legacy alias: `internal-logic`)* | `optimization` | high |
| 7 | `data_type` in (`pure-computation`, `theoretical-derivation`, `personal-context`) + question description includes innovation/breakthrough/new approach  *(legacy alias: `internal-logic`)* | `innovation` | medium |
| 8 | `data_type` = external-data + question description includes risk/choice/which is better | `decision` | medium |
| 9 | `data_type` = mixed + sub-questions >= 3 | `decision` (primary) + independent mode per sub-question | medium |
| 10 | None of the above | `decision` (default) | low |

**Enum closure note**: `internal-logic` is a legacy alias for `pure-computation` / `theoretical-derivation` / `personal-context`. A1's `data_type` enum is `external-data` / `pure-computation` / `theoretical-derivation` / `personal-context` / `mixed`; this table covers all 5 values (external-data via priorities 2,3,8; non-external via 4-7; mixed via 9).

**Default routing**: When no rule matches, always route to `decision` mode, and mark in the Reasoning Log that "routing used default, user confirmation recommended".

---

## Routing Execution Rules

1. Routing executes after the A1 contract completes and before the A2 contract
2. If `route_confidence` = `low`, prompt the user in the Reasoning Log that they can manually specify a mode
3. Mixed-type problems (multiple sub-questions) allow a primary mode + independent mode per sub-question, recorded in A2's `secondary_modes`
4. Routing rules can be overridden by a user-specified mode (priority 1)
