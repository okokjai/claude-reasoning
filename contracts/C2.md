# Contract C2: Inter-Stage Transfer Contract

**Defines the "mandatory transfer fields" and "optional transfer fields" for each stage, ensuring data integrity across stages.**

| Transfer Direction | Mandatory Fields | Optional Fields |
|--------------------|------------------|-----------------|
| A1 -> A0 | `data_type`, `primary_domain` | `sub_question_types`, `specified_mode` |
| A0 -> A2 | `primary_mode`, `route_rule`, `route_confidence` | -- |
| A1 -> A2 | `data_type`, `primary_domain` | `secondary_domains`, `trigger_reason` |
| A2 -> Stage 0 | `primary_mode`, `scale`, `platform_mode`, `can_branch` | `disclaimer_text`, `evidence_cap`, `quality_cap` |
| C0 -> Stage 0 | `user_constraints`, `success_criteria` | `implicit_assumptions` |
| Stage 0 -> Stage 1 | `brainstorm_packet` | `stage_0_uncertainty` |
| A2 -> Stage 1 | `primary_mode`, `scale`, `platform_mode`, `can_branch` | `disclaimer_text`, `evidence_cap`, `quality_cap` |
| A2 -> Stage 3 | `verification_paths` | -- |
| A1 -> Stage 1 | `primary_domain`, `data_type` | `secondary_domains` |
| C0 -> Stage 1 | `user_constraints`, `success_criteria` | `implicit_assumptions` |
| C1 -> Stage 6 | `fallback_mode`, `skip_compensation` | `skippable_stages` |
| Stage 1 -> Stage 2 | `core_problem`, `sub_problems`, `known_facts`, `immutable_constraints` | `unknown_facts`, `sequential_branches` |
| Stage 2 -> Stage 3 | `verification_plan`, `hypotheses`, `claim_registry`, `search_paths_required`, `negative_search_queries` | `null_hypothesis`, `most_dangerous_hypothesis` |
| Stage 3 -> Stage 4 | `evidence_matrix`, `cross_validation`, `evidence_quality`, `source_quality_matrix`, `claim_verification_status`, `data_gap_list` | `unverified_hypotheses`, `tool_calls` |
| Stage 4 -> Stage 5 | `preliminary_conclusion`, `confirmed_facts`, `residual_uncertainty` | `contradictory_evidence_ref`, `domain_specific_analysis` |
| Stage 5 -> Stage 0 | `framing_revision_request` | only when problem framing is invalid and `stage_0_revision_count < 1` |
| Stage 5 -> Stage 5.5 | `preliminary_conclusion` (control flow: only enters when `needs_revision=no`) | -- |
| Stage 3 -> Stage 5.5 | `evidence_matrix`, `source_quality_matrix` | `claim_registry` |
| Stage 5.5 -> Stage 6 | `hallucination_pass`, `hallucination_fail_reason` | -- |
| Stage 5 -> Stage 6 | `hallucination_check`, `fix_requirements`, `needs_revision`, `precision_audit`, `confidence_table` | `revision_branches`, `price_notes` |
| A2 -> Stage 6 | `evidence_cap`, `quality_cap`, `disclaimer_text` | `platform_mode` |
| Stage 6 -> Quality Self-Assessment | `logic_closed`, `evidence_sufficient`, `hallucination_clean` | `confidence`, `conclusion`, `precision_score` |
| Quality Self-Assessment -> Memory | `verdict`, `total_score`, `denominator` | `reasoning_log`, `pattern_asset`, `precision_issues` |

**Execution Rules**:
1. Stage 0 is mandatory for reasoning tasks after C0/A2 and before Stage 1; its `brainstorm_packet` is a candidate input, not evidence, and cannot register claims or bypass verification, hallucination, or quality gates
2. Before each stage begins, check that all "mandatory fields" from the previous stage's output are complete
3. Missing mandatory fields -> return to the previous stage to fill them in; a missing `brainstorm_packet` returns to Stage 0
4. Missing optional fields do not block the flow, but mark it in the Reasoning Log
