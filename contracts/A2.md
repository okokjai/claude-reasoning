# Contract A2: Reasoning Strategy

**Inputs**
- `raw_question` — User's original question
- `data_type` — Data type from A1 output
- `primary_domain` — Primary domain from A1 output
- `primary_mode` — Routed mode from A0 contract output (if A0 not executed, optional user-specified)
- `specified_mode` — (Optional) User-specified mode (if present, overrides A0 routing)

**Outputs (Mandatory)**
- `primary_mode` — Primary mode (`diagnostic` / `design` / `decision` / `optimization` / `innovation`)
- `secondary_modes` — (Optional) List of secondary modes
- `null_hypothesis_type` — Null hypothesis type (`statistical` / `baseline`)
- `conflict_rule` — (Optional) Conflict resolution rule for multi-mode scenarios
- `scale` — Problem scale (`small` / `medium` / `large`)
- `sub_problem_count` — Estimated number of sub-problems from initial decomposition
- `hypothesis_count` — Number of hypotheses to generate (small >= 2, medium/large >= 3)
- `critique_perspectives` — Number of critique perspectives (small = 6 [5 core + Problem Reframing Check], medium = 8, large = 9; Stage 5 mapping table has 12 perspectives total, required set per mode varies — see `stages/stage-5-critique.md` mapping)
- `self_assessment_type` — Self-assessment type (`simplified_scale(/30)` / `full_scale(/50)`)

**Outputs (Optional, domain-triggered)**
- `triggers_disclaimer` — Whether to trigger disclaimer (yes/no)
- `disclaimer_type` — Disclaimer type (`legal` / `medical` / `tax` / `investment`)
- `disclaimer_text` — Full disclaimer text

**Outputs (Mandatory, domain-aware verification paths)**
- `verification_paths` — Search path list dynamically generated from `primary_domain`, each entry containing `{label, search_query, negative_query, failure_condition}`

**Verification Path Generation Rules**:

| Domain | Search Path Template | Negative Search |
|--------|---------------------|-----------------|
| `investment` | 1. `asset+price` 2. `asset+financial report+latest` 3. `asset+news+risk` 4. `asset+analyst+rating` | `asset+scam+controversy` |
| `finance` | 1. `product+interest rate+fees` 2. `product+comparison+review` 3. `institution+risk+complaints` 4. `product+terms+conditions` | `product+pitfalls+risk` |
| `career` | 1. `role+city+salary` 2. `role+skills+requirements` 3. `company+layoffs+news` 4. `role+employment+trends` | `role+drawbacks+risk` |
| `learning` | 1. `course+name+rating` 2. `course+price+comparison` 3. `skill+learning path+recommendation` 4. `platform+reviews+quality` | `course+drawbacks+scam` |
| `relationship` | 1. `issue type+advice+methods` 2. `method+effect+reviews` 3. `book+resource+recommendation` 4. `expert+opinion+research` | `method+side effects+risk` |
| `tech` | 1. `technology+version+comparison` 2. `technology+ecosystem+toolchain` 3. `technology+performance+benchmark` 4. `technology+learning cost+docs` | `technology+limitations+drawbacks` |
| `daily` | 1. `product+city+price` 2. `store+brand+rating` 3. `brand+distributor+city` 4. `product line+city` | `product+pitfalls+bad reviews` |
| `general` | 1. `topic+latest+news` 2. `topic+analysis+opinion` 3. `topic+controversy+criticism` 4. `topic+comparison+alternatives` | `topic+drawbacks+risk` |

**Failure Criteria**: If a path returns 0 valid results, or all results are T3 marketing content, mark that path as "failed".

**Execution Rules (Mandatory)**

1. **Must actually call** `mcp__unified-fetch__status` to detect platform mode (verbal claims are not sufficient)
2. Call format: `mcp__unified-fetch__status()`
3. **Must check** whether sequential-thinking is available
4. Based on returned results, fill output fields:
   - `unified-fetch` any engine available -> `CLI Full Mode` (evidence sufficiency cap 5/5, quality self-assessment cap 45/45)
   - Completely unavailable -> `Desktop Mode` (evidence sufficiency cap 3/5, quality self-assessment cap 24/30)
5. Call results must be recorded in the Reasoning Log
6. **If sequential-thinking is unavailable at runtime (`can_branch=false`), Stage 0, decomposition, hypothesis, and critique stages degrade to linear reasoning**: the same stage/node labels are recorded as text, backtracking is recorded in the critique stage's `revision_branches` as `{original_hypothesis, revision_reason, linear_note}`, and no `sequentialthinking` calls are made

**Outputs (Mandatory, Platform Detection)**
- `platform_mode` — Platform mode (`CLI Full Mode` / `Desktop Mode`)
- `primary_tool` — Primary search tool (`unified-fetch search`)
- `browse_tool` — Browse/scrape tool (`unified-fetch scrape`)
- `evidence_cap` — Evidence sufficiency cap (5/3)
- `quality_cap` — Quality self-assessment cap (45/24)
- `can_branch` — Sequential-thinking available, supports branching/backtracking (`true`/`false`)

> **Note**: Platform detection logic is integrated into the A2 contract's execution rules and is not repeated here. Refer directly to A2 execution rules 1-7 during execution.
