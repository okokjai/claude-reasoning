# Contract A1: Problem Characteristics

**Inputs**
- `raw_question` — User's original question

**Outputs (Mandatory)**
- `data_type` — Data requirement classification (`external-data` / `pure-computation` / `theoretical-derivation` / `personal-context` / `mixed`)  *(legacy alias `internal-logic` = `pure-computation` / `theoretical-derivation` / `personal-context`)*
- `primary_domain` — Primary domain (`investment` / `finance` / `career` / `learning` / `relationship` / `tech` / `daily` / `general`)
- `secondary_domains` — (Optional) List of secondary domains
- `domain_quality_standard` — Domain-specific quality standards
- `trigger_reason` — Specific reason for the data_type classification

**Outputs (Optional)**
- `sub_question_types` — If mixed, list each sub-question's independent type
- `skip_reason` — Non-trigger reason; filled in if any non-trigger condition is met

**Non-Trigger Conditions (skip if any met, do not enter reasoning flow)**
- Single error message with no timeline -> direct debugging, no diagnostic reasoning needed
- Simple fact lookup (single URL can answer) -> answer directly with unified-fetch
- Task requiring code execution -> use auto-fix-loop
- Problem scale < small -> (no such value; `scale` is `small`/`medium`/`large` per A2 — this non-trigger is reserved; `small` uses simplified critique per C1)
